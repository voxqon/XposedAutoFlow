# XposedAutoFlow

一款基于 LSPosed 的 Android 自动化模块。通过组合应用状态、系统状态、时间和位置等条件，自动执行操作，并在退出条件满足时恢复设置。

## 功能

- **灵活的规则**：支持全部满足、任一满足和条件组，可设置触发冷却、动作延迟、退出条件与恢复动作。
- **丰富的条件**：应用前后台和进程状态、屏幕与锁屏状态、充电和电量、Wi-Fi 与蓝牙连接、系统开关、定时、时间范围和地理围栏。
- **系统动作**：启动或停止应用、切换系统开关、连接或断开已保存的 Wi-Fi 和已配对的蓝牙设备、调整媒体音量、播放系统声音、振动、调用系统闹钟，以及发送广播或启动服务。
- **运行记录**：查看规则触发原因、动作结果和恢复记录，可配置日志数量与执行通知。
- **备份与恢复**：手动通过 WebDAV 备份规则和日志数量设置，支持坚果云。
- **界面设置**：支持深色模式、悬浮底栏和隐藏桌面图标。

部分动作依赖 Android 隐藏接口或 ROM 私有能力，实际效果因系统版本和设备而异。Shell 动作默认关闭，开启后命令以目标系统进程的权限执行，请谨慎使用。

## 安装

1. 准备 Android 8.0 或更高版本的设备和可用的 LSPosed 环境。
2. 从 [Releases](https://github.com/voxqon/XposedAutoFlow/releases) 下载并安装 APK。
3. 在 LSPosed 管理器中启用 XposedAutoFlow，确认推荐作用域，并重启设备。
4. 打开应用，创建并启用自动化规则。

推荐作用域包括：

| 作用域 | 用途 |
| --- | --- |
| `android`（系统框架） | 条件监听、规则引擎和动作执行 |
| `com.android.systemui` | 锁屏相关辅助事件 |
| `com.android.settings` | 系统设置辅助事件 |
| `com.miui.home` | 小米桌面辅助事件 |

其中系统框架是规则引擎所需的核心作用域；其他作用域提供相应设备上的辅助事件。模块采用传统 Xposed API 入口。

## 创建规则

一条规则由触发条件、执行动作、退出条件和退出恢复动作组成。例如，进入相机时锁定方向，离开时恢复：

1. 添加“应用进入前台”条件，选择相机应用。
2. 添加“方向锁定”动作，选择锁定。
3. 添加“离开应用”退出条件，选择同一应用。
4. 保存并启用规则。退出条件满足后，模块会尝试恢复捕获到的原始方向设置。

触发条件可选择全部或任一满足，条件组内使用“任一满足”。退出条件之间为“任一满足”。时间范围作为触发限制；仅配置时间范围不会自动结束已触发的规则，需另设退出条件。

定时和持续时长通过周期检查实现，设备深度休眠可能延迟执行，不保证闹钟级准点。多个同时生效的规则修改同一设置时，恢复结果可能受执行顺序影响。

## 地理围栏

围栏支持进入、离开、在范围内和在范围外等条件。可搜索地点、地图选点、使用当前位置或手动输入坐标，并设置半径。仅使用当前位置时请求前台定位权限；地图和地点搜索的可用性取决于网络及设备服务。

地图瓦片由所选地图服务提供，地点搜索使用系统地理编码服务。围栏监听依赖系统定位状态，位置过期或不可用时不会把未知位置当作围栏外。

## 数据与备份

规则和执行日志保存在应用本地；WebDAV 凭据使用 Android Keystore 保护。手动备份包含规则和日志保存数量，不包含执行日志、WebDAV 凭据或 Shell 授权。恢复会在校验后替换本机规则。

WebDAV 使用 HTTPS 目录地址，备份文件名为 `autotasklite-backup.json`。坚果云用户应使用第三方应用密码。备份不会自动运行，上传同名文件会覆盖原文件。

从旧包名 `com.example.autotasklite` 切换到本项目包名 `com.github.voxqon.xposed.autoflow` 时，Android 会将其视为不同应用。请先在旧版中通过 WebDAV 备份，再在新版中恢复，并重新启用 LSPosed 模块和确认作用域。

## 从源码构建

需要 JDK 17、Android SDK 34 和项目内的 Gradle Wrapper。在 Windows PowerShell 中运行：

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

Debug APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。未配置签名时，运行 `.\gradlew.bat :app:assembleRelease` 可生成未签名的 Release APK。

签名构建可通过环境变量 `AUTOFLOW_SIGNING_PROPERTIES` 指定本地配置文件，并通过 `AUTOFLOW_SIGNING_STORE` 指定密钥库。配置文件包含 `STORE_PASSWORD`、`KEY_ALIAS` 和 `KEY_PASSWORD`。请勿将密钥库或签名配置提交到仓库。

`tools/verify-release.ps1` 可检查 Release APK 的 Xposed 入口和运行时资源；签名 APK 可通过 `-Apk` 参数指定。单元测试和静态检查不能代替目标设备上的 LSPosed 验证。

## 常见问题

- **模块未生效**：确认已在 LSPosed 中启用模块、勾选系统框架作用域并重启设备，查看 `XposedAutoFlow` 日志。
- **动作执行失败**：查看运行日志；系统接口、权限和 ROM 差异可能导致部分动作不可用。
- **规则没有恢复**：检查退出条件；若触发时退出条件已成立，需要先变为不成立再重新成立。
- **定时执行延迟**：设备休眠和周期检查可能延后触发。
- **隐藏图标后如何打开**：从 LSPosed 模块详情打开应用，再在设置中恢复桌面图标。
